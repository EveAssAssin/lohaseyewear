# 商城商品頁 → 官網客製文創:商城端串接說明

> 樂活眼鏡官網．2026-08-10．v1.0
> 本文只寫**商城端要做的事**,不含官網內部實作。一頁看完即可開工。

---

## 這是什麼

商城的太陽眼鏡商品頁上加一個 CTA(例:「客製我的專屬刻圖」)。
客人點下去,帶著登入狀態跳到官網的客製文創頁,該頁會自動載入這件商品。
客人挑刻圖、決定雕刻位置,完成後由官網把成品送回商城購物車結帳。

```
商城商品頁
   │  ① can_design = true 才顯示 CTA
   │  ② 呼叫 store-sso-login 取得 reUrl
   │  ③ 立即整頁導轉
   ▼
官網 ssologin.html ──自動──▶ 官網 design.html?nid=2612
                                    │ 客人挑刻圖、拖曳決定位置
                                    ▼
                             回送商城購物車(cart/push)
```

商城只負責 ①②③。之後的事官網處理。

---

## ① 判斷要不要顯示 CTA

商品 API(`/api/site/products`、`/api/site/product`)的 **`can_design`** 為 `true` 才顯示。

這是貴方後台逐品勾選的欄位。`false` 的商品即使有人手動改網址進到官網,
官網也會擋下並提示,不會讓流程繼續。

---

## ② 呼叫 `store-sso-login` 取得 `reUrl`

**Server-to-server 呼叫,不要從瀏覽器端發**(金鑰不可落到前端)。

```
POST https://hqdmyxxrskvllkcedybl.supabase.co/functions/v1/store-sso-login
Content-Type: application/json
```

**Request**

```json
{
  "apiKey": "（官網另行提供)",
  "apiVer": "1.0",
  "erpId": "28095198",
  "erpName": "王小明",
  "next": "/design.html?nid=2612"
}
```

外層包 `data` 的格式也接受,兩種擇一:

```json
{ "data": { "apiKey": "...", "erpId": "...", "next": "..." } }
```

| 欄位 | 必填 | 說明 |
|---|---|---|
| `apiKey` | ✔ | 官網提供。**只放在後端,不可出現在前端程式碼** |
| `apiVer` | | 目前 `1.0`。不符只會記 log,不會擋 |
| `erpId` | ✔ | 該登入會員的 ERP 編號 |
| `erpName` | | 選填。官網會另以 `erpId` 取回完整會員資料,不以此欄顯示 |
| `next` | | 導轉目的地。**傳未編碼的原始字串**,編碼由官網處理 |

**Response**

```json
{
  "status": 200,
  "apiVer": "1.0",
  "reUrl": "https://www.lohasglasses.com/ssologin.html?token=2ac4bf81-...&next=%2Fdesign.html%3Fnid%3D2612",
  "expiresIn": 30
}
```

`reUrl` 是**組好的完整網址**,直接拿去導轉即可,不需要再接任何參數。

---

## ③ 立即整頁導轉

```
302 / location.href = reUrl
```

**兩個限制:**

**一、token 只有 30 秒,從官網回應的那一刻起算。**
取得 `reUrl` 後請立即導轉,中間不要插入其他處理、確認頁或停留頁。
逾時或已使用過的 token 會顯示提示頁,客人可自行點「前往登入」,但體驗不佳。

**二、必須整頁導轉(GET),不可放在 iframe 內。**
兩站為不同註冊網域,瀏覽器的第三方 cookie 限制會讓登入無法建立。

---

## `next` 的規則

**傳原始字串就好**,例如:

```
/design.html?nid=2612
```

不需要 `encodeURIComponent`,官網收到後會自己編碼。這是刻意的設計 ——
先前要求呼叫方自行編碼時,值裡的 `&` 會被瀏覽器當成 `ssologin.html`
自己的參數解析掉,**不會報錯,只是安靜地遺失後半段**。把編碼收回官網這邊,
這個坑就不存在了。

**只接受站內相對路徑**,必須以 `/` 開頭且不可為 `//` 開頭。
帶絕對網址(`https://...`)會回 400。這是為了防止 open redirect ——
避免有人偽造 `next=//惡意網站`,把官網 SSO 當成釣魚跳板。

`next` 不傳也可以,客人會停在官網首頁 —— 但那樣就失去這條流程的意義了。

---

## 未登入的客人怎麼處理

**建議由商城擋下並提示,不要導向官網登入頁。** 兩個理由:

1. 官網登入本身也是走 ERP 帳號。客人若沒有 ERP 編號,到官網登入頁一樣登不進去,
   白跑一趟還多一次失敗經驗。
2. 官網 `login.html` 目前不支援以網址參數指定登入後的目的地,
   客人登入完成會停在會員中心,回不到原本那件商品。

若貴方仍希望走「導向官網登入」,官網可加上
`login.html?next=/design.html?nid=2612` 的支援 —— 但那只解決導回問題,
解決不了「他根本沒有 ERP 編號」。請貴方判斷。

## 回程

客人在官網完成設計後,官網會呼叫商城的 `POST /api/site/cart/push`
把「商品 + 刻圖」送回購物車,並取得 `cart_url` 導客人回商城結帳。
那一段是官網對商城,商城端依既有規格處理即可。

> 目前 `cart/push` 的兩個細節仍在確認中(雕刻檔的位置資訊怎麼帶、
> 無規格商品的 `sid` 傳什麼),詳見《追問三題》。不影響本文的 ①②③。

## 錯誤回應

```json
{ "status": 401, "error": "Invalid apiKey" }
```

| status | 意義 | 處理 |
|---|---|---|
| 200 | 成功 | 取 `reUrl` 導轉 |
| 400 | `Invalid JSON body` | 檢查 Content-Type 與 body 格式 |
| 400 | `Missing required field: erpId` | `erpId` 為空 |
| 400 | `next must be a site-relative path...` | `next` 不是以 `/` 開頭的站內路徑 |
| 401 | `Invalid apiKey` | 金鑰錯誤 |
| 405 | `Method not allowed` | 必須用 POST |
| 500 | `Internal server error` | 官網端異常,**可重試** |

## 測試

金鑰交付後,先用 curl 確認拿得到 `reUrl`:

```bash
curl -X POST https://hqdmyxxrskvllkcedybl.supabase.co/functions/v1/store-sso-login \
  -H "Content-Type: application/json" \
  -d '{"apiKey":"（金鑰)","erpId":"28095198","next":"/design.html?nid=2283"}'
```

拿到的 `reUrl` 直接貼進瀏覽器,應該會自動登入並停在客製文創頁,
頁面上顯示該商品的名稱、價格與圖片。

**測試商品請用 `nid=2283`**(造型太陽-0000-BEJ-QY,庫存 99)。
其餘可文創商品庫存皆為 1,不適合反覆測試。
