# A. 官網這一側

## A1. 客製眼鏡布（年度生日禮）— 唯一整條都在官網跑的歷程

這是生日禮裡我方完整掌握的一條，也是最長的一條。

### ① 進站與資格

`cloth.html` **不需登入就能玩編輯器**，登入是在「存檔」那一刻才擋。
（刻意的：先讓人做出東西，再要求登入，比一進門就擋走的人少。）

登入後打 `cloth` 函式查狀態，三道閘**順序固定不可調換**：

| 順序 | 狀態 | 客人看到 |
|---|---|---|
| 1 | 本年度已完成 | 「一年一件，明年才能再做」；載入他存的那一張、顯示取貨門市、停用存檔鈕，**編輯區照樣能玩** |
| 2 | 被退件待重做 | 退件原因 + 請他重做。**不佔額度、不看生日月** |
| 3 | 非生日月 | 主後端回的那一句（官網不自己算月份） |
| — | 資格查不到 | 「系統異常，請聯繫客服」 |

⚠ 第 2 條必須排在第 3 條前面。客人若在生日月最後一天送出、隔天被退件，
照生日月擋等於**退件把他今年的禮物沒收了**，而畫面只會說「限生日當月」。

⚠ 資格查不到時是 **fail-closed（擋住）**。放行才危險——我方一抖就變成
全站沒有生日限制，客人做得出來、師傅照做，沒有人會發現。

> 內部測試帳號 `28095839` 在白名單裡，不受一年一件限制。

### ② 做圖

三個來源：刻圖市集挑一張 ／ 上傳自己的圖 ／ 直接在畫布上畫。
上傳的圖會自動描圖成線稿（potrace），然後可以拖曳、縮放、旋轉。

### ③ 送出前的確認彈窗

| 勾選 | 預設 | 必填 |
|---|---|---|
| 我知道取貨時要出示貼文，也願意分享作品在網站上，並確認設計不再修改 | 未勾 | **必勾** |
| 我確認擁有這張圖的使用權；若有侵權疑慮，樂活可能退件並請我重新設計 | 已勾 | **必勾** |
| 我願意讓其他客人使用我的圖案 | 已勾 | 可取消 |

**取貨門市必填**，三層擋：前端不給送、`cloth` 函式回 `006`、
資料庫 CHECK（`cloth_designs_store_required`，2026-09-14 主後端加的）。

### ④ 送出之後

```
存檔 status=new
   └→ 加工中心(cloth-lab.html)
        ├→ 完成 status=done ─→ 會員中心顯示「已完成」
        │                    ─→ 進眼鏡布分享牆（目前 113 件）
        │                    ─→ APP 透過 cloth-feed 抓得到
        ├→ 退件 rejected ───→ 客人回 cloth.html 重做（不佔額度）
        └→ 封存 archived
```

**退件原因**（代碼 → 客人看到的話）：

| 代碼 | 客人看到 |
|---|---|
| `line_too_thin` | 線條太細，雕刻後會斷掉 |
| `out_of_bounds` | 圖案超出可雕刻範圍 |
| `low_quality` | 圖片解析度不足，刻出來會模糊 |
| `content` | 圖案內容不適合雕刻 |
| `other` | （自由填寫；兩個都沒有才回「此設計無法製作」） |

### ⑤ 查進度與取貨

會員中心 →「我的客製眼鏡布」：狀態、取貨門市、完成日期。
完成時的文案是「已完成，**前往領取前請務必先聯絡門市**」——
刻意不寫「可到門市領取」，因為東西有沒有送到、人在不在，官網不知道。

### ⑥ 上牆

完成的作品出現在 `cloth.html` 下方的分享牆：**隨機排序**（每次載入換順序、
分頁不重複）、**姓名遮罩在伺服器端做**（王小明 → 王＊＊）。
後台可以單件隱藏（`wall_hidden`），與 `status` 是兩件事。

## A2. 生日分享牆（birthday.html 最下方）

**照片不是官網產生的。** 是門市幫壽星拍的生日照，存在主後端，
同一批也出現在 APP 的「生日專屬回憶」。官網只是唯讀的一個窗口。

- 目前線上 **9 筆**
- 官網**只能隱藏、不能刪除**——來源在主後端，我方刪不掉也不該刪
- 後台隱藏的做法是記 `item_id`，由 `bday-wall` 過濾

⚠ 隱藏是在快取之外做的，所以按下去立刻生效；但上游同時在新增照片，
**總數不一定會變少**。

## A3. 送禮給別人（`design.html?gift=1`）

不是壽星本人的歷程，是「替壽星過生日」的那一條。

```
選一張刻圖 → 做成客製刻圖太陽眼鏡 → 商城下單付款
   → 對方收到領取連結 gift-claim.html?c=<領取碼>
   → 對方【登入會員】才領得走（禮物要進到某個會員名下）
```

領取碼本身就是憑證，不登入也**看得到**是什麼禮物，但**領**一定要登入。

## A4. 我的票券（會員中心）

生日票券（配鏡折 $1,000）**當月自動匯入**，官網這一側是唯讀的清單。
沒有票券時顯示「目前沒有票券。生日票券會在生日當月自動匯入。」

⚠ **轉贈要開 APP**，官網不做——這是刻意的，不是還沒做。

## A5. 預約門市

官網只顯示左手系統的五個固定類型（諮詢／配鏡／調整／取件／視力健檢），
而且只畫**該顧問真的有名額**的那幾種。

⚠ 門市在左手後台自訂的「生日配鏡／生日健檢／生日贈品／生日DIY眼鏡布」
**官網看不到**——左手沒有任何一支 API 列得出門市自訂的預約項目。
已去信詢問。現況不影響正確性：客人選的是那五種之一，不會約錯，
**不同步的是名字，不是時段**。

# C. 整條鏈上會斷在哪裡

依發生機率排：

1. **會員資料沒填生日** → 整個生日禮什麼都拿不到，而且客人不會知道原因。
   官網四個地方都寫了「那一欄一定要填」，但沒有任何一頁會主動檢查並提醒。
2. **`SITE_API_KEY` 沒設或失效** → 眼鏡布資格查不到，**所有人**看到
   「系統異常」。這是 fail-closed 的代價，也是正確的選擇——
   但代表輪替金鑰時漏掉 `cloth` 這支的症狀是全面中斷。
3. **未綁定門市的會員** → 上游 `login` 不回手機號，指名送禮那條路對他們無效。
4. **門市自訂預約項目** → 官網顯示不到（A5）。
5. **退件發生在生日月之後** → 已處理（閘門順序），但這一條沒有被真實流量
   跑過幾次。

# D. 一句話總結

**官網真正「做事」的只有一條：客製眼鏡布。**
其餘的生日禮，官網的角色是說明（birthday.html）、是唯讀窗口
（票券、生日分享牆）、或是把人帶到別的地方（門市、APP、商城）。

所以生日禮出狀況時，第一個要問的是「這件事在哪裡執行」——
在官網的我方當天能修，在 APP／門市／主後端的不行。
