## 2-1 `next` 可以攜帶 query string——但必須整串 URL-encode

可以。`ssologin.html` 以 `URLSearchParams.get('next')` 取值（自動解碼），
驗證通過後以 `location.replace(next)` 跳轉，query string 完整保留。

**但有一個會靜默出錯的情況，請務必注意。** 實測四種寫法：

| 貴方送出的 `next` 值 | 官網實際跳轉到 | 結果 |
|---|---|---|
| `/design.html?nid=2612` | `/design.html?nid=2612` | ✅ 正確 |
| `/design.html?nid=2612&from=shop` | `/design.html?nid=2612` | ⚠ **`&from=shop` 被吃掉** |
| `encodeURIComponent('/design.html?nid=2612&from=shop')` | `/design.html?nid=2612&from=shop` | ✅ 正確 |
| `https://www.lohasglasses.com/design.html?nid=2612` | `/market.html` | ❌ 被安全檢查擋下 |

第二列是問題所在：`next` 值裡若含 `&`，後面的部分會被瀏覽器當成
`ssologin.html` 自己的參數解析掉，**不會報錯，只是安靜地遺失**。
目前只帶 `nid` 不會踩到，但日後多一個參數就會。

**因此請一律使用 `encodeURIComponent` 編碼整個 `next` 值：**

```js
const url = reUrl + '&next=' + encodeURIComponent('/design.html?nid=' + nid);
```

**另外**：`next` 只接受站內相對路徑（須以 `/` 開頭、且不可為 `//`）。
帶絕對網址會被安全檢查擋下並靜默退回 `/market.html`。
這是為了防止 open redirect（避免有人偽造 `next=//惡意網站`
把我方 SSO 當成釣魚跳板），此限制會保留。

## 2-2 SSO 呼叫規格

**`erpName` 若為空該傳什麼**

傳空字串 `""` 即可，不要省略欄位。

原因：官網在 SSO 完成後，會另外以 `erpId` 向 ERP 取回完整會員資料
（姓名、手機、Email、生日），畫面顯示一律以那份為準，
`erpName` 不作為顯示來源。

**token 30 秒從何時起算**

從**我方產生 token 的當下**起算，也就是貴方呼叫 `store-sso-login`、
我方回應 `reUrl` 的那一刻，不是從貴方開啟連結起算。

因此請在取得 `reUrl` 後**立即導轉**，中間不要插入其他處理或停留頁。
逾時或已使用過的 token 會顯示提示頁，使用者可自行點「前往登入」。

# 四、禮物中心

官網刻圖市集將新增「送禮」流程：會員 A 買一份「刻圖 ＋ 眼鏡」送給會員 B。
A 選好刻圖、眼鏡、規格之後，可選兩種履約方式：

| 方式 | 說明 | 收件地址 |
|---|---|---|
| **宅配到府** | A 在商城結帳時直接填收件地址（可填 B 家） | A 在商城填，官網不經手 |
| **門市兌換** | 付款後發一張兌換券到 B 的帳號，B 到門市出示、現場配鏡雷刻 | 沒有地址 |

兩條路的前半段完全相同，都是官網把「商品 ＋ 刻圖 ＋ 刻圖位置」推進購物車，
由 A 在商城完成付款。差別只在付款之後。

> 設計上刻意避開的事：官網不儲存任何收件地址。
> 宅配的地址在貴方系統、門市兌換沒有地址，官網只保管刻圖與禮物關係。

## 4-1 需求一：`cart/push` 增加 `gift` 區塊（兩條路都需要）

```json
"gift": {
  "is_gift": true,
  "gift_id": "官網的禮物編號（uuid）",
  "fulfillment": "store",
  "recipient_erpid": "28095198"

```

| 欄位 | 說明 |
|---|---|
| `is_gift` | 這筆是禮物 |

| `fulfillment` | `ship` 宅配／`store` 門市兌換 |
| `recipient_erpid` | 收禮會員（`store` 必填；`ship` 可空） |

## 4-2 需求二：付款完成回拋 webhook（兩條路都需要）

官網不知道 A 付了沒。沒付款就讓禮物成立，等於白送。

```

Header: X-Shop-Key: （由官網另發給貴方的金鑰，與票券金鑰不同把）
```

```json

  "order_trade_no": "商城訂單編號",

```

官網回應 `{ "code": "200" }`。非 200 請重試 3 次（間隔 1 / 5 / 30 分鐘）。
同一 `gift_id` 重複送不會出錯，官網以 `order_trade_no` 做冪等處理。

請用**付款完成**而非建立訂單的時機。與票券 `redeem` 相反：
票券怕鎖定逾時所以要早，禮物則是付款前不能讓人領走。

另請一併回拋這些事件：

| event | 時機 | 適用 | 額外欄位 |

| `gift_paid` | 付款完成 | 兩者 | `order_trade_no` |
