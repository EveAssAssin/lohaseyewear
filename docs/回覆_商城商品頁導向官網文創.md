# 回覆:商城商品頁 → 官網文創

> 樂活眼鏡官網．2026-08-09
> 回覆貴方「商城商品頁 → 官網文創」流程提案。

流程沒有問題，我方同意照此設計。以下逐題回覆。

---

## 一、`next` 可以攜帶 query string——但**必須整串 URL-encode**

可以。`ssologin.html` 以 `URLSearchParams.get('next')` 取值（會自動解碼），
驗證通過後用 `location.replace(next)` 跳轉，query string 完整保留。

**但有一個會靜默出錯的情況，請務必注意。** 實測四種寫法：

| 貴方送出的 `next` 值 | 官網實際跳轉到 | 結果 |
|---|---|---|
| `/design.html?nid=2612` | `/design.html?nid=2612` | ✅ 正確 |
| `/design.html?nid=2612&from=shop` | `/design.html?nid=2612` | ⚠ **`&from=shop` 被吃掉** |
| `encodeURIComponent('/design.html?nid=2612&from=shop')` | `/design.html?nid=2612&from=shop` | ✅ 正確 |
| `https://www.lohasglasses.com/design.html?nid=2612` | `/market.html` | ❌ 被安全檢查擋下 |

第二列是問題所在：`next` 值裡若含 `&`，後面的部分會被瀏覽器當成
`ssologin.html` 自己的參數解析掉，**不會報錯，只是安靜地遺失**。
目前只帶 `nid` 不會踩到，但日後多一個參數就會。

**因此請一律使用 `encodeURIComponent` 編碼整個 `next` 值。**

```
reUrl + '&next=' + encodeURIComponent('/design.html?nid=2612')
```

**另外**：`next` 只接受**站內相對路徑**（必須以 `/` 開頭、且不可為 `//`）。
帶絕對網址會被安全檢查擋下，靜默退回 `/market.html`。
這是為了防止 open redirect（避免有人偽造 `next=//惡意網站`
把我方 SSO 當成釣魚跳板），會保留。

## 二、SSO 呼叫規格

**`erpName` 若為空該傳什麼**

傳空字串 `""` 即可，不要省略欄位。

原因：官網在 SSO 完成後，會另外以 `erpId` 向 ERP 取回完整會員資料
（姓名、手機、Email、生日），畫面上顯示的一律是那份資料。
`erpName` 在此流程中不作為顯示來源。

> 我方會再確認 `store-sso-login` 目前是否把 `erpName` 當必填擋下，
> 若會，我方調整為允許空字串，屆時另行告知。

**token 30 秒從何時起算**

從**我方產生 token 的當下**起算，也就是貴方呼叫 `store-sso-login`、
我方回應 `reUrl` 的那一刻。不是從貴方開啟連結起算。

因此請在拿到 `reUrl` 後**立即導轉**，不要先做其他處理或讓使用者停留在中間頁。
逾時或已使用過的 token 會顯示提示頁，使用者可自行點「前往登入」。

## 三、落地頁

我方會建置 `https://www.lohasglasses.com/design.html?nid=<商品編號>`。

同意貴方的設計：**只傳商品編號，不傳名稱與價格**，我方以 `nid`
回頭呼叫 `POST /api/site/product` 取得完整資料。
價格一律以貴方回傳為準，我方不做任何本地價格計算。

---

## 四、未綁定 ERP 編號的會員

**建議由貴方擋下並提示，不要導向官網登入頁。** 理由有二：

1. 官網登入本身也是走 ERP 帳號。客人如果沒有 ERP 編號，
   到官網登入頁一樣登不進去，等於白跑一趟還多一次失敗經驗。
2. 目前官網 `login.html` **不支援用網址參數指定登入後的目的地**，
   客人登入完成後會停在會員中心，回不到原本那件商品。

如果貴方仍希望走「導向官網登入」這條，我方可以加上
`login.html?next=/design.html?nid=2612` 的支援，
但那只解決導回問題，解決不了「他根本沒有 ERP 編號」這件事。

請貴方判斷哪種對客人比較好。

## 五、票券折抵

**建議第一版不放在落地頁入口，改放在設計完成後、回拋購物車之前。**

理由：這條流程的起點是商品頁，客人的心理狀態是「我要買這個」，
一進落地頁就先問「要不要用票券」會打斷設計流程。
而且票券鎖定只有 30 分鐘（可續到 4 小時上限），
客人若在設計階段就鎖定，很容易在文創過程中逾時。

我方規劃：客人完成設計、按下「加入購物車」時，
才顯示「你有 N 張可用票券」讓他選，選了才呼叫 `coupon/lock`，
接著立刻帶 `lock_token` 進 `cart/push`。這樣鎖定時間最短、逾時風險最低。

票券 API（`list` / `lock` / `extend` / `unlock`）我方已完成串接並實測通過，
不需貴方額外配合。
