# 禮物中心 — 商城端需求規格

> 樂活眼鏡官網．2026-08-09．v0.1（提案，待貴方確認）
> 對應官網功能：會員 A 買一份「刻圖 ＋ 商品」送給會員 B。

---

## 一、要做什麼

官網新增「禮物中心」。與現有流程最大的不同是 **付款的人和收貨的人不是同一個**：

```
A 在官網挑刻圖 + 挑商品 + 寫祝福語
        ↓
A 到商城付款（付的是自己的錢）
        ↓
官網把領取連結給 A，A 自行傳給 B
        ↓
B 登入官網領取，此時才填自己的收件姓名／電話／地址
        ↓
商城依 B 填的地址出貨
```

現行 `cart/push` 草案假設「下單者＝收貨者」，所以這條流程有三個缺口。以下逐一說明。

---

## 二、缺口一：`cart/push` 需要知道「這筆是禮物」

**現況**：官網把商品推進購物車後，商城無從得知這筆將來要送人。

**需求**：`POST /api/site/cart/push` 增加一個 `gift` 區塊。

```json
{
  "client_id": "28095839",
  "main": {
    "nid": 1234,
    "sid": 18,
    "amount": 1,
    "design": {
      "design_id": "官網端的設計編號",
      "preview_url": "https://....supabase.co/.../preview.png",
      "engraving_url": "https://....supabase.co/.../engraving.svg"
    }
  },
  "plus_buy": [ { "type": "engraving_fee", "amount": 1 } ],

  "gift": {
    "is_gift": true,
    "gift_id": "官網的禮物編號（uuid）",
    "hold_shipping": true
  }
}
```

| 欄位 | 說明 |
|---|---|
| `is_gift` | 這筆是禮物 |
| `gift_id` | 官網禮物編號。後續兩支介面都靠它對應 |
| `hold_shipping` | **付款後暫緩出貨**，等官網補上收件資訊再放行 |

**`hold_shipping` 為什麼必要**：付款完成時，收禮人還沒領取，訂單上根本沒有收件地址
（或只有送禮者自己的地址）。若照常進出貨流程，會直接寄錯人。

---

## 三、缺口二：付款完成要回拋通知官網

**現況**：官網不知道 A 付了沒。沒付款就開放領取，等於白送。

**需求**：訂單**付款完成**時，商城打一支 webhook 到官網。

```
POST https://hqdmyxxrskvllkcedybl.supabase.co/functions/v1/gift-webhook
Header: X-Shop-Key: （由官網提供給貴方的金鑰，與票券金鑰不同把）
```

```json
{
  "event": "gift_paid",
  "gift_id": "官網的禮物編號",
  "order_trade_no": "商城訂單編號",
  "paid_at": 1754584200,
  "amount": 3500
}
```

**官網回應**

```json
{ "code": "200" }
```

- 非 `200` 請重試，建議 3 次（間隔 1 / 5 / 30 分鐘）
- 同一 `gift_id` 重複送不會出錯，官網以 `order_trade_no` 做冪等處理
- 呼叫時機請用**付款完成**而非建立訂單。與票券 `redeem` 不同：
  票券怕鎖定逾時所以要早，禮物則是付款前不能讓人領走

**另請一併回拋這兩個事件**，官網要據此更新禮物狀態並通知會員：

| event | 時機 | 官網動作 |
|---|---|---|
| `gift_paid` | 付款完成 | 開放 B 領取 |
| `gift_shipped` | 實際出貨 | 通知 A 與 B，附物流資訊 |
| `gift_cancelled` | 訂單取消／退款 | 禮物作廢，若 B 已領取則通知 |

---

## 四、缺口三：收禮人的收件資訊要能補進訂單

**現況**：訂單建立時收件人未知。

**需求**：官網在 B 完成領取後呼叫，把收件資訊補上並解除 `hold_shipping`。

```
POST /api/site/order/recipient
```

```json
{
  "gift_id": "官網的禮物編號",
  "order_trade_no": "商城訂單編號",
  "recipient": {
    "name": "王小明",
    "phone": "0912345678",
    "zipcode": "104",
    "address": "台北市中山區XX路1號5樓"
  },
  "release_shipping": true
}
```

**回應**

```json
{ "code": "200", "data": { "order_trade_no": "...", "status": "ready_to_ship" } }
```

- 若訂單已出貨／已取消，請回明確錯誤碼，官網會擋下並提示會員聯繫客服
- 收件資訊只送一次；B 若要改地址，官網會先擋，需人工處理

## 五、需要貴方確認的問題

1. **`hold_shipping` 在貴方系統可行嗎？** 若訂單無法暫停，替代方案是：
   訂單先掛「待指定收件人」狀態，不進出貨佇列，等 `order/recipient` 進來才轉正常單。
   哪一種對貴方成本較低？

2. **收禮人一直不領怎麼辦？** 官網預計設 90 天失效。屆時要走退款嗎？
   若要，是全額退給 A、還是轉成 A 帳上的購物金？這牽涉貴方的退款流程，請指示。

3. **B 領取時填的地址，運費怎麼算？** 若 A 付款當下已收運費，而 B 的地址是外島／超商取貨，
   費用會有落差。是統一運費、還是要在領取時補收？

4. **webhook 金鑰**：官網會另發一把給貴方（與票券的 `X-Site-Key` 不同把），
   避免任一把外洩時波及另一邊。請確認貴方能設定自訂 Header。

5. **測試環境**：`lohas-shop-test.onrender.com` 上能否先開這三支？
   官網端會先做到「待付款」狀態，接上後就能全鏈路測試。

## 六、官網端的進度

以下已完成或進行中，不需貴方配合：

- 禮物資料表與狀態機（Supabase）
- 禮物中心頁面（我送出的／我收到的）
- 送禮流程：選刻圖 → 選商品（用貴方 `api/site/products`）→ 填祝福語 → 指定收禮人
- 領取頁面（連結領取 ＋ 指定會員領取）

卡住的只有金流那一段，也就是本文件的三個缺口。
